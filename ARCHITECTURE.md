# Mnenie — Архитектура системы

> **Mnenie** («Мнение») — платформа, которая собирает резонансные новости из СМИ,
> социальных сетей и форумов, анализирует обсуждения методами NLP/ML и
> прогнозирует общественную реакцию: уровень доверия, поляризацию, вероятный
> «вердикт общества» и динамику изменения мнения во времени.

Документ описывает **полное продуктовое и техническое видение**. Репозиторий
содержит работающий **MVP** (backend + аналитический движок + frontend с
реальными графиками), который реализует ядро этой архитектуры на детерминированных
эвристиках, чтобы запускаться без внешних API и GPU. Места, где продакшен-версия
заменяет эвристику на полноценные ML-модели, помечены **`[PROD]`**.

## 1. Продуктовое видение (Senior PM)

### Проблема
Резонансные новости распространяются быстрее, чем общество успевает их осмыслить.
Пользователю (журналисту, аналитику, модератору, исследователю) трудно понять:
- верят ли люди новости и насколько,
- насколько общество расколото,
- какие аргументы у сторон,
- не является ли волна реакции скоординированной (боты/ИПСО).

### Целевые пользователи
1. **Журналисты / фактчекеры** — оценка достоверности и реакции.
2. **PR / коммуникационные команды** — мониторинг кризисов.
3. **Исследователи / социологи** — изучение поляризации.
4. **Модераторы платформ** — обнаружение информационных кампаний.

### Ключевые метрики продукта
- Time-to-insight (от появления новости до готового анализа).
- Точность прогноза вердикта (back-testing на исторических новостях).
- Доля обнаруженных координированных кампаний (precision/recall).
- Retention аналитиков (WAU/MAU).

### MVP scope (реализовано в репозитории)
- Сбор → нормализация → анализ → агрегация → API → дашборд.
- Карточки новостей, индекс доверия, %верят/не верят/не определились,
  поляризация, вероятность правды, «Суд общества», кластеры аргументов,
  детектор ботов, динамика мнения, фильтры, рейтинги.

## 3. Пайплайн сбора данных (Data Scientist)

Этапы (см. `server/src/pipeline/`):

1. **Collect** — коннекторы к источникам (RSS, News API, соц-API, скраперы).
   Каждый элемент: `{source, url, text, author, ts, lang, geo}`.
2. **Deduplicate** — near-dup по SimHash/MinHash заголовков и текстов.
3. **Normalize** — чистка HTML, эмодзи→токены, нормализация юникода,
   определение языка (`fastText lid.176` `[PROD]`; в MVP — эвристика по алфавиту).
4. **Enrich** — привязка комментариев к новости, гео по профилю/IP,
   расчёт «возраста» аккаунта, частоты постинга.
5. **Analyze** — прогон NLP/ML-моделей (раздел 5).
6. **Aggregate** — сведение по новости в метрики и snapshot временного ряда.
7. **Index** — запись в аналитическое хранилище + обновление рейтингов.

Расписание: near-real-time для «горячих» новостей (приоритетная очередь по
скорости роста обсуждения), батч раз в N минут для остальных.

## 4. Структура базы данных

Каноническая схема — `server/src/db/schema.sql` (Postgres-совместимый DDL,
в MVP применяется к SQLite/in-memory). Основные таблицы:

```
sources(id, name, domain, type, country, political_bias, reliability_score, created_at)
news(id, title, summary, url, topic, country, language, published_at, ingested_at)
news_sources(news_id, source_id)                  -- M:N новость↔источник
comments(id, news_id, source_id, author_handle, text, language,
         likes, reposts, created_at, account_age_days, post_frequency)
comment_analysis(comment_id, sentiment, emotion, stance, bot_score,
                 argument_cluster_id, toxicity)
news_metrics(news_id, trust_index, believe_pct, disbelieve_pct, undecided_pct,
             polarization, truth_probability, bot_ratio, confidence, verdict,
             updated_at)
opinion_snapshots(id, news_id, ts, believe_pct, disbelieve_pct, undecided_pct,
                  trust_index)                      -- time-series для графиков
argument_clusters(id, news_id, side, label, size, representative_text)
campaigns(id, news_id, score, kind, evidence, detected_at)  -- ИПСО/координация
geo_opinion(news_id, country, believe_pct, disbelieve_pct, volume)
```

Индексы: `news(topic, country, published_at)`, `comments(news_id)`,
`opinion_snapshots(news_id, ts)`. Time-series (`opinion_snapshots`,
`geo_opinion`) в проде живут в ClickHouse для быстрых оконных агрегаций.

## 5. NLP / ML-модели (Data Scientist + Social Psychologist)

Все модели реализованы в `server/src/nlp/`. В MVP — интерпретируемые эвристики
на лексиконах (RU+EN); в проде — трансформеры.

### 5.1 Тональность (Sentiment)
- `[PROD]` дообученный `XLM-RoBERTa` (мультиязычный), выход: pos/neg/neu + score.
- MVP: взвешенный лексикон позитив/негатив + усилители + отрицания.

### 5.2 Классификация мнения / позиции (Stance / Belief)
Определяет отношение комментатора к новости: **верит / не верит / не определился**.
- `[PROD]` stance-detection модель (target = тезис новости), few-shot LLM-разметка
  для обучения.
- MVP: маркеры доверия («подтверждаю», «так и есть», «source») vs недоверия
  («фейк», «вброс», «не верю», «постановка»), вопросы/неуверенность → undecided.

### 5.3 Эмоции (Emotion)
- Модель Plutchik/Ekman (гнев, страх, радость, отвращение, удивление, доверие, грусть).
- MVP: лексикон эмоций + интенсивность по пунктуации/капсу.

### 5.4 Выявление ботов и подозрительной активности
Признаки на аккаунт и сообщение:
- возраст аккаунта, частота постинга, шаблонность текста (n-gram повторы),
  near-dup сообщений между аккаунтами (координация), всплески по времени,
  однотипные ссылки.
- `[PROD]` градиентный бустинг / GNN на графе взаимодействий.
- MVP: эвристический скоринг (см. `botDetection.ts`).

### 5.5 Кластеризация аргументов
- Эмбеддинги сообщений (`sentence-transformers`) → HDBSCAN → лейблинг кластеров
  (ключевые фразы / LLM-суммаризация) `[PROD]`.
- MVP: кластеризация по тематическим ключевым словам с репрезентативной цитатой.

### 5.6 Анализ источников
- Репутация домена (история точности, политический уклон), кросс-подтверждение
  факта несколькими независимыми источниками.
- Вклад в `truth_probability`.

### 5.7 Прогноз общественного мнения
- `[PROD]` модель временных рядов / выживания: фичи = текущая динамика, скорость
  роста, доля ботов, репутация источников, сила аргументов сторон. Прогноз траектории
  %верят на горизонт T (Prophet / Temporal Fusion Transformer).
- MVP: модель затухающего тренда с регрессией к равновесию, зависящему от
  truth_probability и текущего импульса (см. `predictor.ts`).

### 5.8 Производные метрики (формулы MVP)
- **Trust index (0–100)** = f(доля верящих, репутация источников, доля ботов,
  кросс-подтверждение).
- **Polarization** = нормированная биполярность распределения позиций
  (макс. при 50/50 верят/не верят, мин. при консенсусе).
- **Truth probability** = ансамбль: репутация источников × кросс-подтверждение ×
  (1 − доля скоординированной активности) × сигнал сторон.
- **Confidence** = f(объём данных, согласованность сигналов, доля ботов).

## 5bis. COMMENTS ANALYTICS (анализ комментариев)

Отдельный экран и пайплайн для глубокого анализа обсуждения под новостью.
Код: `server/src/analysis/comments.ts`, типы — `CommentsAnalytics`.

### Backend-архитектура
```
comments (RawComment[])
   │
   ▼  analyzeCommentsAnalytics(newsId, comments)
   ├─ per-comment NLP: sentiment → stance → emotion → bot-score → near-dup
   ├─ controversy: конфликт с мажоритарным мнением + сила тона + токсичность
   ├─ influence (per-comment): bot × repetition × охват  → low/medium/high
   ├─ кластеризация (партиция, приоритет): suspicious → minority → support/opposition/neutral
   ├─ INFLUENCE DETECTION: coordinated / propaganda-repetition / sentiment-spike / velocity
   └─ heatmap контроверсивности по временным корзинам
   ▼
CommentsAnalytics {summary, clusters, influence, heatmap, comments[]}
```
Кэш в `store.ts` (`getCommentsAnalytics`), оффлайн-снапшот для мобильного
приложения формируется при `npm run ingest`.

### ML-пайплайн (на комментарий)
1. **Sentiment** (лексикон + отрицания/усилители) → score −1..1.
2. **Stance** (маркеры доверия/недоверия + тон-fallback) сдвигает score.
3. **support / against / neutral** = знак итогового lean (порог ±0.15).
4. **Controversy (0–100)** = конфликт с мажоритарным направлением (×) + |score| +
   токсичность + гнев/отвращение.
5. **Bot-probability (0–100)** = эвристика по возрасту аккаунта, частоте,
   near-dup, шаблонности, хэндлу (`botDetection.ts`).
6. **Influence (low/med/high)** = bot × repetition × охват (лайки).
7. **Repetition** = SimHash-отпечаток встречается ≥2 раз (`duplicateOf`).
8. `[PROD]`: трансформер stance/ABSA, эмбеддинги + HDBSCAN для кластеров,
   GNN на графе аккаунтов для координации.

### Кластеры (меньшинство сохраняется отдельно)
Партиция по приоритету, чтобы редкие голоса не растворялись:
`Подозрительные/повторяющиеся` → `Меньшинство/редкие` → `Основная поддержка` /
`Основная оппозиция` / `Нейтральные`.

### INFLUENCE DETECTION SYSTEM
- **coordinated** — доля вероятных ботов;
- **propaganda_repetition** — группы near-dup сообщений;
- **sentiment_spike** — окно с резким перекосом одного мнения;
- **velocity_anomaly** — пик/медиана сообщений (всплеск интереса — обычно
  органический, поэтому НЕ формирует influence-score сам по себе, только
  усиливает фон при наличии ботов/повторов).
Итоговый `influenceScorePct` — взвешенная комбинация манипулятивных признаков.

## 7. Frontend — основные экраны

1. **Лента (Feed)** — карточки новостей: заголовок, сводка, индекс доверия,
   мини-распределение позиций, бейджи (тема, страна, «обнаружена кампания»).
   Фильтры по стране/теме/поиску, сортировка.
2. **Детальная новость** — индекс доверия (gauge), %верят/не верят/не определились
   (donut), поляризация, вероятность правды, эмоции (bar), источники.
3. **Суд общества** — итоговый вердикт, уверенность, аргументы большинства и
   меньшинства, разбивка поддерживают/осуждают/фейк/правда/не определились.
4. **Динамика мнения** — линейный график изменения %верят/индекса во времени +
   прогноз (пунктир).
5. **Карта мнений** — распределение позиций по странам.
6. **Аргументы** — кластеры за/против с размерами и цитатами.
7. **Сравнение источников** — таблица репутаций и подачи.
8. **Кампании/боты** — индикаторы координации, доля ботов, доказательства.
9. **Рейтинги** — самые спорные / самые поляризующие новости.
10. **Аналитика платформы** — общие тренды.
11. **COMMENTS ANALYTICS** — дашборд по комментариям новости: полоса и pie
    support/against/neutral, плитки (противоречивые %, бот-вероятность %,
    influence %), карта контроверсивности (heatmap), панель INFLUENCE DETECTION
    с сигналами, кластеры мнений (включая меньшинство), лента комментариев с
    фильтрами (все/поддержка/против/противоречивые/подозрительные/меньшинство) и
    маркерами на каждом (sentiment, controversy, bot %, influence, повтор).
    Противоречивые — красная рамка, подозрительные — предупреждающий цвет.

Дизайн: тёмная минималистичная тема, акцент на данных, доступные контрасты,
скелетоны при загрузке.

## 8. Социально-психологический слой (Social Psychologist)

- **Поляризация** трактуется как биполярность распределения, а не просто разброс —
  два сильных лагеря опаснее равномерного шума.
- **Эмоциональная карта** (Plutchik) помогает отличить рациональное обсуждение от
  морального возмущения (гнев/отвращение → вирусность, но низкая истинность).
- **Эффект эхо-камер**: кластеры аргументов + источники показывают замкнутость
  нарративов.
- **Вердикт общества** агрегирует не голоса, а *взвешенные* позиции (вес ↓ для
  ботов и токсичного спама), приближая «здоровое» коллективное суждение.

## 9. Этика, риски, приватность

- Не храним PII; авторы — псевдонимизированные хэндлы.
- «Bot-score» и «вердикт» — вероятностные сигналы, а не факты; UI это коммуницирует.
- Прозрачность: каждая метрика объяснима (какие факторы повлияли).
- Защита от манипуляции самой системой (понижение веса скоординированных волн).

## 10. Дорожная карта

- **M1 (этот MVP):** ядро анализа, дашборд, сидированные данные.
- **M2:** реальные коннекторы (RSS/Reddit/Telegram), очередь, Postgres.
- **M3:** трансформерные модели сентимента/стэнса/эмбеддингов, обучение на разметке.
- **M4:** прогнозная модель временных рядов, back-testing точности вердиктов.
- **M5:** детектор ИПСО на графах, алёрты, мультиязычность, мобильный клиент.
