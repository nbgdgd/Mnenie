# Mnenie ⚖ — суд общества над новостями

**Mnenie** анализирует конфликтные, спорные и резонансные новости и прогнозирует
общественную реакцию: уровень доверия, поляризацию, эмоции, вероятный «вердикт
общества» и динамику изменения мнения во времени.

Система собирает обсуждения из СМИ, соцсетей и форумов, прогоняет их через
NLP/ML-пайплайн (тональность, классификация мнений, выявление ботов,
кластеризация аргументов, анализ источников, прогноз мнения) и показывает всё на
современном минималистичном дашборде.

> Это работающий **MVP**. Полное продуктовое и техническое видение —
> в [`ARCHITECTURE.md`](./ARCHITECTURE.md). Описание API — в [`API.md`](./API.md).

## Возможности

- 📊 **Индекс доверия (0–100)**, % верят / не верят / не определились.
- ⚖ **Суд общества**: итоговый вердикт, уверенность, аргументы большинства и
  меньшинства, разбивка поддерживают/осуждают/фейк/правда.
- 📈 **Динамика мнения во времени** + прогноз модели (пунктир).
- 🧠 **Эмоциональная реакция** (Plutchik), **поляризация общества**,
  **вероятность правды**.
- 🤖 **Выявление ботов и координированных кампаний** (ИПСО).
- 🗺 **Карта распространения мнений** по странам.
- 🧩 **Кластеризация аргументов** сторон, **сравнение источников**.
- 🔥 **Рейтинги** самых спорных и самых поляризующих новостей.
- 🔎 Фильтры по странам, темам, поиску.

## Анализ (как это работает)

Каждый комментарий проходит: нормализацию → определение языка → тональность
(лексикон + отрицания/усилители) → классификацию позиции (верит/не верит/не
определился) → эмоции → бот-скоринг (возраст аккаунта, частота, near-dup) →
тематический кластер. Затем движок (`server/src/analysis/engine.ts`) **взвешивает
мнения** (вес ↓ у ботов и токсичности) и считает индекс доверия, поляризацию,
вероятность правды, вердикт, гео-разрез и временной ряд с прогнозом.

В MVP модели реализованы как интерпретируемые эвристики (RU+EN), чтобы работать
без внешних API и GPU. Места под продакшен-модели (трансформеры, временные ряды,
GNN) помечены `[PROD]` в коде и `ARCHITECTURE.md`.

## Запуск

Требуется Node ≥ 20.

```bash
npm install            # установит зависимости обоих воркспейсов

# терминал 1 — backend (http://localhost:4000)
npm run dev:server

# терминал 2 — frontend (http://localhost:5173, проксирует /api на backend)
npm run dev:web
```

Открыть <http://localhost:5173>.

### Живые новости (реальный парсинг)

Система умеет собирать **настоящие** новости и комментарии из публичного API
[Hacker News](https://github.com/HackerNews/API) (без ключей), прогонять их через
тот же NLP-движок и сохранять результат:

```bash
npm run ingest --workspace=server
```

Команда:
- тянет топ-истории HN, их комментарии и данные авторов (возраст аккаунта,
  активность → реальные бот-сигналы);
- классифицирует тему, тональность, эмоции, позицию, считает вердикт и кампании;
- пишет `server/data/live.json` (backend начинает отдавать живые данные вместо
  сидов) и `mobile/assets/snapshot.json` (предрасчёт, вшивается в APK).

Если `live.json` отсутствует, backend работает на сид-данных. Мобильное приложение
**работает офлайн** на вшитом снапшоте реальных новостей и автоматически
переключается на live-backend, если он доступен по адресу из `app.json`.

### Прочие команды

```bash
npm run seed --workspace=server   # прогнать анализ по всем новостям в консоли
npm test  --workspace=server      # юнит-тесты NLP-движка
npm run build                     # сборка backend + web-frontend
```

## 📱 Android-приложение (React Native + Expo)

Нативное приложение под Android живёт в `mobile/` и подключается к тому же
backend.

```bash
cd mobile
npm install
npm start            # запустить Metro; нажать "a" для Android (эмулятор/устройство)
# либо:
npm run android      # сразу собрать и запустить на Android
```

**Данные без сервера.** В APK вшит снапшот реальных новостей
(`mobile/assets/snapshot.json`), поэтому приложение показывает контент **сразу,
офлайн, без запущенного backend**. Обновить снапшот: `npm run ingest`.

**Адрес backend (опционально).** Если backend запущен и доступен, приложение
автоматически берёт свежие данные с него (короткий таймаут, иначе — снапшот). По
умолчанию адрес `http://10.0.2.2:4000` (так Android-эмулятор видит `localhost`
host-машины). Для физического телефона укажите IP компьютера в `mobile/app.json`
→ `expo.extra.apiBase` (например `http://192.168.1.50:4000`) или через переменную
`EXPO_PUBLIC_API_BASE`. Телефон и компьютер должны быть в одной сети.

**Сборка APK/AAB** (нужен аккаунт Expo и EAS CLI):

```bash
cd mobile
npx eas build -p android --profile preview   # APK для установки на устройство
```

Локально проверить, что приложение собирается без эмулятора:

```bash
cd mobile
npm run typecheck    # проверка типов
npm run bundle       # экспорт Android JS-бандла (Metro)
```
